# 零一扬官网运维手册

## 状态与边界

正式域名为 `https://www.01yang.space`，裸域仅跳转到正式域名。GitHub 仓库为 `01-Yang/01yang-company-website`。本项目不提供登录、表单、数据库或付费接口，生产站点只需要 Nginx 和静态文件。

备案对应域名为 `01yang.space`，已核实编号为 `闽ICP备2026024313号-2`。核查时网站名称仍为“零一扬的个人简历”；名称/用途变更和既有进行中订单必须独立处理，不能取消旧订单或修改25th记录。

**流水线成功不代表公网已开放。** `/etc/01yang-company-website/public-enabled` 是管理员控制的开放开关；不存在时外部HTTPS返回503，服务器回环请求可进行内部验收。普通部署用户不能创建这个开关。实际进度见本文末尾交付记录。

## 本地环境与私有配置

使用Node `24.16.0`，执行`npm ci`安装锁定依赖，不使用无锁升级。真实配置入口为：

```text
~/.local/share/01yang-company-website/ops/运维私有配置.env
```

目录权限700、文件600。公开模板为`deploy/ops.env.example`，只包含空值占位、非敏感默认值和说明；不要在模板填真实凭据。配置由`scripts/ops.mjs`显式读取，不使用根目录`.env.local`，避免网站构建加载运维凭据。分组、变量组和流水线ID只是资源索引，不会自动修改云端配置。

官网五年PAT名称为`01yang-company-flow-readonly-20310828`，平台回显到期日期为`2031-08-28`，已登记`YUNXIAO_TOKEN_EXPIRES_AT`。它只允许读取流水线、运行实例和运行任务，不能创建资源、同步配置或触发发布。初始化写凭据单独短期使用，完成后撤销并移除本地副本；撤销是否完成以交付记录为准。

SSH私钥保留在仓库外，配置仅登记路径：人工运维使用`id_ed25519_01yang_company`，CI使用独立的`id_ed25519_01yang_company_ci`。后者在服务器授权时必须带`restrict`和强制命令`/usr/local/lib/01yang-company-website/receive-release.sh`，只接受`publish`，不能执行任意shell、人工回滚或sudo命令。两把密钥不得混用。

云效专属变量组只将CI私钥存入加密变量`COMPANY_DEPLOY_SSH_KEY`，不存入只读PAT或初始化令牌。`deploy/known_hosts`版本控制服务器公钥，SSH严格验证指纹；它不是私钥。可选`YUNXIAO_WEBHOOK_URL`是私有触发地址，按凭据保管，不能输出到日志或公开文档。

本地环境文件是权限受限的明文，不是加密保险箱。令牌、私钥及私有Webhook不要出现在命令参数、截图、日志或聊天中。Git只能恢复模板，不能恢复凭据；换电脑的恢复顺序见下文。

```bash
npm run ops:status
npm run ops:runs
npm run ops:check
```

`OPS_EXPECT_PUBLIC`只影响健康检查预期，不会开启网站。备案门槛未解除时保持`false`。

## 初次初始化、DNS与TLS

以下操作属于管理员职责，不放入日常云效部署脚本。

1. 记录25th配置SHA、发布指针和页面响应；旧站正在发布时，等其结束后再配置共享Nginx。
2. 将已校验的`deploy/`文件传到服务器专属临时目录，以管理员执行`bash bootstrap.sh init`。脚本只建立官网目录、用户和维护态入口，并把变更前状态保存到`/var/backups/01yang-company-website/`。
3. 阿里云DNS仅添加`www`、`@`两条A记录到目标ECS，TTL600，不加泛解析。确认权威解析生效，官网域名返回维护态而非25th。
4. 管理员执行`bash bootstrap.sh tls`，使用独立Certbot目录申请覆盖`www.01yang.space`及`01yang.space`的证书，安装TLS模板和独立定时器。
5. 用独立参数执行续期演练，不运行会修改25th配置的泛化证书安装命令：

```bash
certbot renew --dry-run --no-random-sleep-on-renew --config-dir /etc/letsencrypt-01yang \
  --work-dir /var/lib/letsencrypt-01yang --logs-dir /var/log/letsencrypt-01yang
systemctl status 01yang-company-certbot.timer --no-pager
```

Nginx日志沿用系统对`/var/log/nginx/*.log`的轮转策略，核对规则覆盖官网独立文件；不要重复配置同一日志轮转。

## 云效与日常发布

GitHub PR及main推送的`static-site-checks`检查负责类型、Lint、静态构建及安全检查器测试，不接触生产凭据。`main`禁止强推和删除；单人维护不要求额外审批人。已有Linux CI成功记录，后续修改仍需重新通过检查。

云效使用公共Git源，Webhook仅匹配main push，源码拉取不需要GitHub长期令牌。构建在云效公共香港构建机完成，不在2GiB ECS上安装依赖或编译官网。`deploy/ci-build.sh`准备经SHA-256核验的固定Node版本，执行`npm ci`和`npm run ci:verify`；构建失败不得进入发布。

`deploy/ci-publish.sh`只打包`dist/client/`，用临时权限600的CI密钥文件，经校验主机指纹的SSH连接向`01yang-deploy`发送`publish`，制品从标准输入流式传输。临时密钥与压缩文件在步骤退出时清理；不传源码、node_modules、服务端构建产物或运维配置。

服务器只由管理员通过`bootstrap.sh`安装root所有、部署用户只读的`receive-release.sh`、`release.sh`和校验器。CI强制命令入口接收制品后调用`release.sh`；人工运维密钥仍以`01yang-deploy`运行受控发布工具。TLS和初始化需要管理员，日常发布无通用sudo权限。

制品根目录必须包含`index.html`、`index.rsc`、`404.html`、robots、sitemap、静态资源、`version.json`和`SHA256SUMS`；版本文件记录完整Git SHA及UTC构建时间。成功发布的原始压缩包与SHA-256文件保存在ECS的`shared/archives/`，不是云效内置制品库。当前公共`ArtifactUpload` schema不可用，本方案不购买制品服务，也不依赖该步骤。

YAML在`deploy/aliyun-flow.yml`维护；提交文件不会自动同步云效配置。仅在需要变更流水线时，通过短期写凭据运行`node scripts/ops.mjs sync`并核对远端保存结果，随后撤销临时凭据。当前方案不使用VMDeploy、不安装或注册旧Runner、不创建新服务连接。旧手动Runner不能安全复用；探索期间建立的空主机组不作为发布依赖，清理状态见交付记录。

私密变量组在控制台单独关联：编辑官网流水线 → 变量和缓存 → 通用变量组 → 关联`01yang-company-website-prod-secrets`（OpenAPI ID `43787`）。当前中心站YAML校验不接受该数字API ID，因此不将它直接填入`variableGroups`；更新YAML后仍需复核此关联。已验证本项目的配置同步不会移除该关联。加密变量名为`COMPANY_DEPLOY_SSH_KEY`，只关联官网流水线`5230708`；流水线分组为“零一扬公司官网”（`150804`）。

流水线串行发布，并由服务器独立锁二次保护。首次人工运行并验收后才接入GitHub Webhook，至少用一次真实main提交验证自动触发，成功/失败通知也必须实际验证；仅有YAML、Webhook或通知配置不算验收通过。

发布顺序：获得独立锁 → 安全解包和完整校验 → 检查旧站 → 原子切换current → 检查官网版本、首页、关键资源和旧站 → 记录成功并归档制品。保留最近5个成功版本，current/previous引用的版本额外保护；对应旧归档及其校验文件一起清理，`shared/static/`不自动删除。中断或验收失败时恢复官网上一指针；SIGKILL/断电无法依靠进程trap处理，需按人工回滚步骤恢复。

## 备案就绪与正式开放

核对或变更网站名称、用途及接入信息，确认实际网站与备案一致。短信、实人核验由本人完成，不因CI成功跳过。

只有备案与内部验收完成后，管理员才创建`/etc/01yang-company-website/public-enabled`空文件。该文件不入仓库，不允许流水线创建。随后从外部检查HTTPS首页200、裸域308、静态资源和备案链接，并将本地`OPS_EXPECT_PUBLIC`调整为`true`。

紧急维护时仅移除这个官网开放开关文件即可恢复外部503；不删除发布目录，不改25th默认入口。开关变化无需重启Nginx。

## 回滚、排查与恢复

使用人工运维密钥连接，以官网部署用户执行；CI密钥不能运行回滚命令：

```bash
/usr/local/lib/01yang-company-website/release.sh --rollback <已成功的版本ID>
```

回滚重新校验目标文件并执行双站健康检查；失败时恢复回滚前指针。没有活动版本的首次预部署失败，会恢复无活动版本状态并继续维护态。

- 校验失败：不忽略错误、不直接解包覆盖current；从对应CI提交重新生成可信制品。
- 构建失败：查看云效或GitHub检查，旧版本不应改变。
- 官网503：先核对备案门槛和开放开关，不能直接认定发布失败。
- HTTPS异常：检查官网证书有效期、独立定时器和错误日志，不重置全站证书。
- 失败版本与下载文件：确认不被current/previous引用、没有发布运行后，才清理官网目录内的明确目标；不清空shared/static，不跨项目递归删除。
- 服务器恢复：重新初始化官网资源，从已验证的ECS制品归档、其加密备份或对应Git提交恢复；详细顺序见下一节。不要假设云效存在可下载的历史制品。

## 凭据轮换与加密备份

### 轮换顺序

- 五年只读PAT：新建官网专属、仅含同样读取权限的令牌，记录名称和精确到期时间；在权限600的私有配置中替换后验证`ops:status`、`ops:runs`，再撤销旧令牌并更新加密备份。不要靠扩权解决读取失败。
- CI SSH密钥：生成新官网专用密钥，先把新公钥以相同`restrict,command="/usr/local/lib/01yang-company-website/receive-release.sh"`限制追加到官网用户授权文件，保留旧钥；更新云效加密变量及`OPS_CI_SSH_KEY_FILE`路径索引，实际验证发布和“非publish命令被拒绝”，成功后精确移除旧公钥行、旧变量值和过期私钥副本。不覆盖整个`authorized_keys`，不删除人工运维钥。
- 人工运维SSH密钥：先追加带`restrict`的新公钥，使用第二个连接验证能以`01yang-deploy`执行所需运维，更新`OPS_SSH_KEY_FILE`再精确移除旧钥。保留已验证连接直到完成，不修改25th授权。
- 私有Webhook：重新生成后先更新GitHub触发配置和私有索引，验证一条真实main提交只触发官网流水线，再使旧地址失效。初始化写令牌在配置验收完成后撤销；撤销结果与无本地残留都应确认。
- SSH服务器指纹：主机迁移或密钥变更时，从可信管理员通道核对新公钥后更新`deploy/known_hosts`，经PR和CI验证。不能为了通过发布而关闭严格校验，或把未经核对的网络扫描结果直接当成可信指纹。

### 备份清单与恢复验证

在密码管理器加密附件或加密卷中保存以下内容；解锁密码/恢复密钥另行保管。不要先在仓库、普通同步盘或未加密临时目录组装包含私钥的备份。

| 备份对象 | 必须包含 |
| --- | --- |
| 本机凭据 | 官网私有环境配置、两把独立SSH私钥及公钥；不包含已撤销初始化令牌或25th凭据 |
| 发布数据 | 官网`shared/archives/`及校验文件、成功记录、`shared/static/`、current/previous对应的版本与指针记录 |
| 服务器配置 | 官网Nginx文件、`/etc/01yang-company-website/`、受控发布工具、官网用户的`authorized_keys`、独立Certbot目录及官网证书service/timer |
| 恢复记录 | Git提交、活动版本ID、归档SHA-256、备份时间、证书到期时间和当时维护/开放状态；不记录密钥正文 |

`/var/backups/01yang-company-website/`中的初始化备份只用于该次变更恢复，不是完整站点备份，也不是加密异地备份。ECS上的归档与站点同盘，同样不能替代离机加密备份。每次凭据轮换、关键配置变更后更新备份；制作后在受控加密位置试解密并核对归档校验，确认恢复密钥确实可用。

换电脑时：克隆公开源码并安装锁定依赖 → 从加密备份恢复官网私有配置和SSH密钥 → 恢复目录700/文件600权限并更新本机路径索引 → 检查只读`ops:status`、`ops:runs`、`ops:check`。不要用空模板覆盖恢复的私有配置，也不要恢复已撤销令牌。

服务器恢复时：管理员先按隔离要求建立官网维护态入口和受控工具 → 恢复官网SSH授权与独立TLS/续期配置 → 从加密备份取出可信制品并在归档目录执行`sha256sum --check <版本ID>.tgz.sha256` → 恢复只追加的共享静态资源 → 人工运维密钥以`01yang-deploy`运行`release.sh <制品路径>` → 验证官网内部资源、版本和25th响应 → 验证公网维护态及独立证书续期。无可信归档时从记录的Git提交重新执行完整CI构建，不绕过校验。备份中的`public-enabled`只作为历史状态记录，恢复时不自动创建；仍需重新核对备案和开放条件。
