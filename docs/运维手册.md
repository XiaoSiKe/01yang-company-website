# 零一扬官网运维手册

## 状态与边界

正式域名为 `https://www.01yang.space`，裸域仅跳转到正式域名。GitHub 仓库为 `01-Yang/01yang-company-website`。本项目不提供登录、表单、数据库或付费接口，生产站点只需要 Nginx 和静态文件。

备案对应域名为 `01yang.space`，已核实编号为 `闽ICP备2026024313号-2`。核查时网站名称仍为“零一扬的个人简历”；名称/用途变更和既有进行中订单必须独立处理，不能取消旧订单或修改25th记录。

**流水线成功不代表公网已开放。** `/etc/01yang-company-website/public-enabled` 是管理员控制的开放开关；不存在时外部HTTPS返回503，服务器回环请求可进行内部验收。普通部署用户不能创建这个开关。实际进度见本文末尾交付记录。

同机共享Nginx属于运维和权限隔离，不是独立服务器的安全边界。常规发布不修改Nginx、不重启服务；管理员重复初始化前必须检查链接和路径，异常即停。

## 本地环境与私有配置

使用Node `24.16.0`，执行`npm ci`安装锁定依赖，不使用无锁升级。真实配置入口为：

```text
~/.local/share/01yang-company-website/ops/运维私有配置.env
```

目录权限700、文件600。公开模板为`deploy/ops.env.example`，仅含变量名和说明；不要在模板填真实值。配置由`scripts/ops.mjs`显式读取，不使用根目录`.env.local`，避免网站构建加载运维凭据。SSH私钥保留在仓库外，配置仅登记路径。

五年PAT只允许读取流水线、运行实例和运行任务，不能创建资源、同步配置或触发发布。初始化写凭据单独短期使用，完成后撤销并移除本地副本。令牌值不要出现在命令参数、截图、日志或聊天中。

这是权限受限的本地明文配置，不是加密保险箱。请在自己的密码管理器或加密备份中另存必要凭据；Git只能恢复模板，不能恢复密钥。重新克隆项目不影响项目外配置；换电脑时恢复私有配置和独立SSH密钥后运行只读检查。

```bash
npm run ops:status
npm run ops:runs
npm run ops:check
```

`OPS_EXPECT_PUBLIC`只影响健康检查预期，不会开启网站。备案门槛未解除时保持`false`。

## 初次初始化、DNS与TLS

以下操作属于管理员职责，不放入日常云效部署脚本。

1. 记录25th配置SHA、发布指针和页面响应；旧站正在发布时，等其结束后再配置共享Nginx。
2. 将已校验的`deploy/`文件传到服务器专属临时目录，以管理员执行`bash bootstrap.sh init`。脚本只建立官网目录、用户和维护态入口，并把变更前状态保存到`/var/backups/01yang-company-website/`。
3. 阿里云DNS仅添加`www`、`@`两条A记录到目标ECS，TTL600，不加泛解析。确认权威解析生效，官网域名返回维护态而非25th。
4. 管理员执行`bash bootstrap.sh tls`，使用独立Certbot目录申请覆盖`www.01yang.space`及`01yang.space`的证书，安装TLS模板和独立定时器。
5. 用独立参数执行续期演练，不运行会修改25th配置的泛化证书安装命令：

```bash
certbot renew --dry-run --config-dir /etc/letsencrypt-01yang \
  --work-dir /var/lib/letsencrypt-01yang --logs-dir /var/log/letsencrypt-01yang
systemctl status 01yang-company-certbot.timer --no-pager
```

Nginx日志沿用系统对`/var/log/nginx/*.log`的轮转策略，核对规则覆盖官网独立文件；不要重复配置同一日志轮转。

## 云效与日常发布

GitHub PR的`static-site-checks`检查负责类型、Lint、静态构建及安全检查器测试，不接触生产凭据。`main`禁止强推和删除；单人维护不要求额外审批人。

云效使用公共Git源，Webhook只匹配main push。源码拉取不需要GitHub长期令牌。构建节点下载经SHA-256核验的Node固定版本，执行`npm ci`和`npm run ci:verify`；只上传`dist/client/`，不传源码、node_modules或服务端构建产物。

制品根目录必须包含`index.html`、`index.rsc`、`404.html`、robots、sitemap、静态资源、`version.json`和`SHA256SUMS`。版本文件记录完整Git SHA及UTC构建时间。云效下载制品后，以`01yang-deploy`执行受控发布工具。

YAML在`deploy/aliyun-flow.yml`维护。初始化取得官网主机组ID后替换占位符；仅提交YAML不会改变云效配置。使用短期写凭据执行`node scripts/ops.mjs sync`，并核对远端保存结果。不得用25th的流水线或主机组ID替代。

同一ECS加入官网专属组时沿用原有ECS接入方式，复用已装Runner，不重装、不改其原配置。流水线设为串行运行，避免并发覆盖下载文件。首次人工运行并验收后才接入GitHub Webhook，至少用一次真实提交验证自动触发，不能只检查配置存在。

发布顺序：获得独立锁 → 安全解包和完整校验 → 检查旧站 → 原子切换current → 检查官网版本、首页、关键资源和旧站 → 记录成功。保留最近5个成功版本并保护当前/前一版本，共享哈希资源不自动删除。中断或验收失败时恢复官网上一指针；SIGKILL/断电无法依靠进程trap处理，按下一节人工恢复。

## 备案就绪与正式开放

核对或变更网站名称、用途及接入信息，确认实际网站与备案一致。短信、实人核验由本人完成，不因CI成功跳过。

只有备案与内部验收完成后，管理员才创建`/etc/01yang-company-website/public-enabled`空文件。该文件不入仓库，不允许流水线创建。随后从外部检查HTTPS首页200、裸域308、静态资源和备案链接，并将本地`OPS_EXPECT_PUBLIC`调整为`true`。

紧急维护时仅移除这个官网开放开关文件即可恢复外部503；不删除发布目录，不改25th默认入口。开关变化无需重启Nginx。

## 回滚、排查与恢复

以官网部署用户执行：

```bash
/usr/local/lib/01yang-company-website/release.sh --rollback <已成功的版本ID>
```

回滚重新校验目标文件并执行双站健康检查；失败时恢复回滚前指针。没有活动版本的首次预部署失败，会恢复无活动版本状态并继续维护态。

- 校验失败：不忽略错误、不直接解包覆盖current；从对应CI提交重新生成可信制品。
- 构建失败：查看云效或GitHub检查，旧版本不应改变。
- 官网503：先核对备案门槛和开放开关，不能直接认定发布失败。
- HTTPS异常：检查官网证书有效期、独立定时器和错误日志，不重置全站证书。
- 失败版本与下载文件：确认不被current/previous引用、没有发布运行后，才清理官网目录内的明确目标；不清空shared/static，不跨项目递归删除。
- 服务器恢复：重新初始化官网资源，从云效制品或对应Git提交恢复，再验收证书与域名；凭据从独立安全备份恢复。
