# 零一扬科技公司官网 PRD

## Problem Statement

福州零一扬网络科技有限公司需要一个正式、可信且具有鲜明品牌辨识度的官网，用于说明公司是谁、提供哪些服务、如何开展合作，并让潜在客户能够快速发起联系。

当前公司业务覆盖 AI SaaS、AI 模型 API 聚合与接入、软件定制开发、网络技术服务和 AI 教育。若只是简单罗列技术名词，访问者难以理解公司能解决什么问题，也无法感知公司的产品判断、工程能力与品牌气质。官网需要把这些分散能力组织成一条清晰的价值叙事，同时维持极简黑白、动效克制、接近 Apple 的高品质体验。

## Solution

建设一个以 www.01yang.space 为正式地址的单页公司官网：

- 首屏以“福州零一扬网络科技有限公司”为主标题，并用“从零到一，让人工智能真正落地！”明确品牌主张。
- 使用黑白动态光束作为主视觉，用胶囊导航、玻璃拟态和大留白形成统一的极简科技感。
- 通过服务卡片解释五类核心服务，用“定义—构建—成长”的实现路径展示合作方式。
- 通过公司与创始人介绍建立主体可信度，同时避免未经证明的行业排名、客户数据或效果承诺。
- 用清晰的邮件入口完成合作转化，首期不引入表单后端或用户账户。
- 页面滚动时内容以基于视口的轻量入场动效出现；顶部导航在滚动后平滑转为毛玻璃状态。
- 支持手机、平板与桌面布局，支持键盘、屏幕阅读器与减少动态效果偏好。

## User Stories

1. As a 潜在企业客户, I want 一眼看懂公司主要做 AI 与软件服务, so that 我能快速判断是否值得继续浏览。
2. As a 潜在企业客户, I want 看见明确的业务结果而不只是技术名词, so that 我能理解服务与我的业务有什么关系。
3. As a 创业者, I want 了解公司是否能把一个想法做成可运行产品, so that 我能评估合作可行性。
4. As a 产品负责人, I want 了解 AI SaaS 服务包含哪些阶段, so that 我能估算双方需要投入的工作。
5. As a 技术负责人, I want 了解模型 API 接入能力, so that 我能判断它是否适合现有系统。
6. As a 技术负责人, I want 看到“模型聚合与接入”的清晰表述, so that 我不会误解服务为未经授权的模型转售。
7. As a 需要定制系统的客户, I want 了解可开发的产品形态, so that 我能判断需求是否在服务范围内。
8. As a 运行业务系统的客户, I want 了解部署、集成和维护支持, so that 我能考虑长期运行成本。
9. As a 企业管理者, I want 了解 AI 培训面向的对象与价值, so that 我能评估团队赋能合作。
10. As a 非技术客户, I want 通过简洁语言理解服务, so that 我不需要先掌握大量专业术语。
11. As a 访问者, I want 在首页、服务、关于和联系之间快速跳转, so that 我能直接找到目标内容。
12. As a 访问者, I want 导航持续可见且不遮挡内容, so that 我在长页面中不会迷失。
13. As a 访问者, I want 导航显示当前所在区块, so that 我能理解浏览位置。
14. As a 手机用户, I want 使用清晰的移动菜单, so that 我能单手完成导航。
15. As a 手机用户, I want 按钮和菜单拥有足够大的触控区域, so that 我不会误触。
16. As a 访问者, I want 页面内容在滚动时自然出现, so that 浏览过程流畅且有层次。
17. As a 容易被动态效果影响的用户, I want 网站尊重减少动态效果偏好, so that 我能舒适地阅读内容。
18. As a 键盘用户, I want 能跳过导航并直接进入正文, so that 我不必重复遍历菜单。
19. As a 键盘用户, I want 所有链接具有清楚的焦点状态, so that 我始终知道当前位置。
20. As a 屏幕阅读器用户, I want 页面拥有正确的标题层级和语义区域, so that 我能理解内容结构。
21. As a 低性能设备用户, I want 动态背景在能力不足时不影响内容读取, so that 网站仍然可用。
22. As a 搜索引擎访问者, I want 搜索结果显示准确的公司名与服务描述, so that 我能判断页面相关性。
23. As a 分享链接的用户, I want 链接拥有统一的品牌标题、描述和分享图片, so that 分享内容看起来正式可信。
24. As a 潜在客户, I want 通过一个低门槛入口联系公司, so that 我能快速开始沟通。
25. As a 潜在客户, I want 联系入口显示目标邮箱与微信二维码, so that 我能选择邮件或微信快速沟通。
26. As a 访问者, I want 了解公司法定主体与创始人, so that 我能确认合作对象。
27. As a 合规审阅者, I want 页面避免未经验证的绝对化宣传, so that 网站不会制造不必要的承诺风险。
28. As a 合规审阅者, I want 后续能补充隐私政策、服务条款与备案信息, so that 正式运营信息完整。
29. As a 维护者, I want 视觉规范和动效令牌被集中记录, so that 后续页面保持一致。
30. As a 维护者, I want 业务内容与视觉组件保持清晰边界, so that 后续替换文案不会重写动效逻辑。
31. As a 维护者, I want 生产构建可重复通过, so that 网站能够稳定部署。
32. As a 维护者, I want 依赖保持在完成需求所需的最小集合, so that 长期升级成本可控。

## Implementation Decisions

- 首期采用单页信息架构，导航使用页内深链接。服务详情页、案例页和文章系统等待真实内容后再建设。
- 技术栈采用 Next.js App Router 语义、React、TypeScript、Tailwind CSS 与 Vinext/Vite 静态导出，由阿里云 ECS 上的独立 Nginx 站点提供服务。
- 顶部导航采用 PillNav：桌面为透明宽导航与白色文字，移动端为可展开菜单；滚动后收拢为半透明深色玻璃胶囊。
- 页面业务 CTA 统一采用 SpecularButton，以跟随鼠标的 WebGL 边缘高光提供交互反馈。
- 导航当前状态由区块进入视口触发，不依赖路由跳转。
- 首屏动态背景采用 Three.js 与 React Three Fiber 渲染 Beams；该模块只在客户端加载，避免服务端 WebGL 依赖。
- 微交互和滚动入场使用 GSAP；滚动触发模块按需加载，减少首屏不必要执行。
- Contact 模块底部、页脚上方使用单条横向 LogoLoop 展示核心前端技术栈，不加入竖向循环或额外装饰轨道。
- 五项服务使用 CardSwap 自动换位展示，并提供键盘、触控和鼠标均可操作的暂停/继续控制。
- 服务模块下方使用 AccordionGallery 预留未来项目展示位；当前为五张已本地化的占位图，真实项目上线时替换图片、标题与链接。
- 滚动入场只改变 transform 与 opacity；导航形态、折叠画廊和文字扫光使用各自受控过渡，并在减少动态效果时停用非必要动画。
- 检测 prefers-reduced-motion：关闭连续光束动画、滚动入场和非必要过渡，保留全部可读内容。
- 网站使用黑白语义令牌而不是在业务组件中随机选择颜色；详细规则记录在设计系统文档中。
- 图标统一使用同一套线性 SVG 图标，不使用 Emoji 作为结构图标。
- 首页服务名称对外使用“AI 模型 API 聚合与接入服务”，不把“AI 中转站”作为正式营销名称。
- 页面不展示虚构客户 Logo、案例、调用量、排名、节省比例或用户评价。
- 联系方式使用 `mailto:1241798750@qq.com` 邮件深链接，并在联系区展示用户提供的微信二维码。
- 微信二维码采用深色玻璃外框，二维码本体保持标准黑码白底，不进行生成式重绘或颜色反相。
- 首期不收集访客个人信息，因此不实现联系表单、Cookie 分析、账户或数据库。
- 元数据使用公司法定全称、品牌名、服务描述和正式 www 域名。
- 分享图片使用独立的品牌横图；网站正文不依赖该图片。
- 所有关键链接最小高度不低于 44px，并保留可见焦点样式。
- 正文按中文阅读习惯控制行宽和行高，移动端不允许横向滚动。
- 第三方组件实现经过适配，并保留对应许可证与版权说明。

## Testing Decisions

- 测试以用户可观察行为为准，不断言具体 DOM 层级、GSAP 时间线内部状态或 Three.js 材质实现。
- 最高层验收缝隙是生产构建：类型检查与打包必须成功，根路径必须返回非错误响应。
- 导航行为验收：首页、服务、关于、联系锚点可达；滚动后导航进入玻璃状态；移动菜单可用鼠标、触摸和键盘打开与关闭。
- 内容行为验收：每个导航目标都有实际内容，没有死链接；邮件入口包含可见邮箱地址；微信二维码可以识别。
- 响应式验收：至少覆盖 375px、768px、1024px 和 1440px 宽度；不得出现横向滚动、重叠导航或固定元素遮挡。
- 无障碍验收：检查跳转正文链接、标题层级、焦点顺序、触控目标、图标装饰性标记、颜色对比和 aria-current。
- 动效验收：普通模式下入场不引发布局位移；减少动态效果模式下内容立即可见、滚动不被劫持、WebGL 不连续刷新。
- 性能验收：光束组件客户端加载，首屏文案与导航不等待 WebGL 才出现；联系区文字与邮箱不等待二维码下载。
- SEO 验收：页面语言为简体中文；标题、描述、canonical 基础域名、Open Graph 与 X 元数据与公司主体一致。
- 本项目没有可复用的既有测试先例；首期以构建、静态检查和高层交互验收为主，若后续加入表单或多路由，再引入端到端测试。

- 在线联系表单、CRM、邮件发送后端与数据库。
- AI API 实际网关、计费、密钥管理和客户控制台。
- 课程售卖、学习系统与证书系统。
- 博客、新闻、案例详情和内容管理系统。
- 多语言页面。
